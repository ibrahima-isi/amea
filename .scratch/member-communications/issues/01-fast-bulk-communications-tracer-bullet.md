# 01: Fast bulk communications tracer bullet (hybrid engine & live chunked sending)

**What to build:** Make the Administration bulk communications workflow (`/communications.php`) work reliably and fast end-to-end. Persist Member communications, per-recipient delivery rows, and a shared daily send quota counter in the database (with a Doctrine migration aligned with the baseline schema), introduce the persistent `SMTPKeepAlive` batch transport seam sending from `noreply@aeesgs.org` with `Reply-To` from association contact settings, replace slow full-table hydration with aggregate SQL stats and accurate SQL `COUNT(*)` recipient previews (excluding trashed Members and missing/invalid emails), support Status (including `Diplômé(e)` mapped across legacy imported values), Institution, Consentement CGU, and Statut KYC (default excluding `REJECTED`) filters, render messages inside the branded bulk-communication template with safe line breaks and `{{prenom}}`/`{{nom}}` personalization, require confirmation showing the exact recipient count, dispatch queued recipients in fast live chunks (`/communications-dispatch.php`) with atomic claiming, stale-claim recovery, and a live progress bar, and allowlist `MAIL_DAILY_LIMIT`, `MAIL_BATCH_SIZE`, `MAIL_MAX_ATTEMPTS`, and `MAIL_SEND_PAUSE_MS` in Stellar runtime-env rendering.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] Doctrine migration and aligned baseline schema create `communications`, `communication_recipients`, and `mail_daily_usage` tables cleanly on both fresh MariaDB and SQLite test setups.
- [x] Mail service exposes a persistent batch SMTP transport seam (`SMTPKeepAlive = true`), sends with `From: noreply@aeesgs.org` and `Reply-To` from configured `contact_email` (fallback `contact@aeesgs.org`), accurately reports per-recipient failure instead of ignoring errors, and preserves `APP_ENV=test` transport suppression when no test transport is injected.
- [x] Loading `/communications.php` computes summary cards via a single aggregate SQL query (active Members, reachable Members with valid email, missing-email count, today's sent count vs `MAIL_DAILY_LIMIT`) without hydrating all Member objects.
- [x] `/communications-count.php` executes a SQL `COUNT(*)` excluding soft-deleted Members and empty/invalid emails, and matches the exact filter set used when queueing: Status (mapping `ELEVE`/`PUPIL`, `ETUDIANT`/`STUDENT`, `STAGIAIRE`/`TRAINEE`, `Diplômé(e)`/`Diplômé`/`GRADUATE`), Institution, Consentement CGU, and Statut KYC (default excluding `REJECTED`, with explicit overrides).
- [x] Branded bulk-communication email template renders escaped plain-text content with `<br>` line breaks (no raw HTML injection, no double-escaped `<br>` tags) and personalizes `{{prenom}}` and `{{nom}}`.
- [x] Submitting `/communications.php` requires CSRF verification and a confirmation modal showing the exact recipient count, creates the communication and recipient rows in one fast request, preserves a non-JS/redirect flash message containing `email(s)`, and drives live chunked delivery via CSRF-protected `/communications-dispatch.php` (up to 25 recipients per chunk, atomic claiming, 5-minute stale-claim recovery, shared daily quota enforcement transitioning to `PAUSED_LIMIT` when reached).
- [x] Stellar runtime-env rendering allowlists `MAIL_DAILY_LIMIT`, `MAIL_BATCH_SIZE`, `MAIL_MAX_ATTEMPTS`, and `MAIL_SEND_PAUSE_MS` with existing validation rules.
- [x] Automated PHPUnit unit/integration tests verify filtering, legacy status mapping, template rendering/escaping, persistent batch reuse, atomic claiming, stale-claim recovery, daily quota cap enforcement, and controller dispatch contracts.
