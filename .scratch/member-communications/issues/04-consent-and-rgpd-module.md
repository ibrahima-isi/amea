# 04: Dedicated Consent & RGPD module (/consent.php) & isolated cgu_token lifecycle

**What to build:** Restore Consent reminders and GDPR Deletion requests as a dedicated Administration module cleanly separated from bulk communications. Add `cgu_token`, `cgu_reminder_sent_at`, `consent_refused_at`, and `deletion_requested_at` to `students` via a Doctrine migration aligned with the baseline schema. Introduce the `'consent'` module permission in `UserService`, user creation/editing forms, staff navigation whitelist, router, and sidebar (*Adhérents et dossiers → Consentement & RGPD*). Update `AcceptTermsController` on the Public website to look up active Members exclusively by `cgu_token` (completely decoupled from KYC `review_token`), persist `consent_refused_at` on refusal, persist `deletion_requested_at` and notify `contact_email` on deletion request, and invalidate `cgu_token` on acceptance or deletion request. Build `/consent.php` with fast aggregate summary cards, paginated and AJAX-searchable pending-consent and manual-selection Member lists, fast hybrid Consent reminder sending (targeting pending-consent, all active Members for a terms update, or manually selected Members; generating fresh `cgu_token` links strictly from `PUBLIC_APP_URL`; rendering `cgu-reminder.html`; recording `cgu_reminder_sent_at` on confirmed send), and a **Demandes de suppression** tab listing active Members with deletion requests, linking to each dossier, and providing a direct **"Déplacer vers la corbeille"** action routed through the existing soft-delete workflow when the Staff user also holds `'students'` permission.

**Blocked by:** 01 — Fast bulk communications tracer bullet (hybrid engine & live chunked sending)

**Status:** ready-for-agent

- [x] Doctrine migration and aligned baseline schema add `cgu_token` (`VARCHAR(64) NULL UNIQUE`), `cgu_reminder_sent_at`, `consent_refused_at`, and `deletion_requested_at` to `students`.
- [x] `'consent'` is registered in `UserService::MODULES`, assignable in add/edit staff user forms (*Consentement & RGPD*), automatically held by Super Admin (ID 1), and gates `/consent.php`, `/consent-members.php`, and `/consent-dispatch.php` (never granted implicitly by `'communications'`).
- [x] Sidebar shows **Consentement & RGPD** under *Adhérents et dossiers* only when the Staff user has `'consent'` permission, and staff topbar labels reflect the new route.
- [x] `AcceptTermsController` looks up active (non-trashed) Members strictly by `cgu_token` (rejecting `review_token`); `accept` sets `consent_privacy = 1`, clears `consent_refused_at`, `deletion_requested_at`, and `cgu_token`; `refuse` sets `consent_privacy = 0` and `consent_refused_at` while keeping `cgu_token` valid for the immediate follow-up choice screen; `request_deletion` records `deletion_requested_at`, clears `cgu_token`, and notifies `settings.contact_email`.
- [x] `/consent.php` computes summary counts via aggregate SQL, paginates/searches pending-consent and manual-selection lists server-side (never dumping all Members into the initial DOM), and dispatches Consent reminders through the shared hybrid chunked engine with confirmation modal and live progress.
- [x] Consent reminder generation creates fresh cryptographically random 64-hex-character `cgu_token` values, builds links strictly from `PUBLIC_APP_URL` (failing closed with a clear French error if `PUBLIC_APP_URL` is unavailable), renders `cgu-reminder.html` with recipient name and acceptance URL, and sets `cgu_reminder_sent_at` only upon confirmed delivery.
- [x] **Demandes de suppression** tab lists active (non-trashed) Members with `deletion_requested_at IS NOT NULL`, links to `student-details.php?id=...`, and exposes a CSRF-protected **"Déplacer vers la corbeille"** action using the existing soft-delete lifecycle strictly when the Staff user also holds `'students'` permission.
- [x] Automated unit and integration tests cover `'consent'` permission isolation, `AcceptTermsController` token isolation and state transitions, paginated/searchable member lookup, hybrid Consent reminder dispatch, and deletion-request Trash handoff.
